# 架構原型審查交接

審查對象為本套件實際檔案，不是中心正式系統，也不是已公開產品。請讀 README、ARCHITECTURE、CONTRACTS、IMPLEMENTATION_STATUS、src、tests 與提示詞。

## 給 Claude 或其他模型的提示

```text
請審查我提供的 self-inspection-basic-kit 0.2.0 隔離試行版。
不要自行修改、部署、發 LINE、讀正式資料或取得帳號憑證。
先列你實際讀過的檔案與沒有取得的證據，不把文件分析當成測試。

重點：
1. 六項功能是否有清楚模組邊界與可擴充設定，不需每次重建架構。
2. 設定、角色、案件流轉、現任處理人與名單交集是否一致。
3. 所有寫入是否共用 requestId、版本核對與固定意圖，部分寫入不報成功。
4. 零副作用意圖作廢有無繞過、原 ID 復活或中斷永久卡住。
5. 正式功能未完成時是否真的拒絕，是否有假驗證或共用秘密漏到公開頁面的路徑。
6. 提示詞是否適合 ChatGPT／Gemini 等模型，會不會誘導未經同意部署或誤稱一鍵上線。

有終端能力可先安裝固定版本依賴，在隔離套件跑 npm test、npm run demo、npm run check:release。
沒有就明示未執行。P0／P1／P2 須附 file:line、可觸發情境與必要修正。
不要把已列為未實作的真實替換層當作偷偷完成，也不要要求擴大首版業務。
結論分「架構／原型是否需修訂」與「距正式試行還缺哪些證據」。
即使原型可接受，也不能說已可部署、已發布或已無資安風險。
```

## 審查後的修改順序

設定／文字改稿先沿 schema 與架構；核心缺口加最小回歸測試再修。一般使用者登入、正式私有檔案及真實通知另開範圍，不在審閱名義下自行連正式環境。每輪更新實作狀態和實際驗證結果。須讀新增 web、gas、chunked 與 file-sandbox，核對空身分拒絕、場域範本、分段完整性、檔案公開即拒絕及沒有 sender。
