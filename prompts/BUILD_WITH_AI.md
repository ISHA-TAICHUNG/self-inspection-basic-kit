# 常見大語言模型建置提示詞

目前來源：本套件檔案。日後公開發布，才替換成已核對的 GitHub 網址，不把尚不存在的儲存庫連結當作來源。

## 通用啟動提示詞

以下整段可用於 ChatGPT、Gemini、Claude 或 Codex。先以虛構資料啟動，私有配置另處理。

```text
請協助我建立事業單位的「自主檢查與異常通報基礎系統」。
依我提供的 ISHA 基礎套件檔案／已發布儲存庫建置，不另起一套架構。

請先讀 START_HERE.md、ARCHITECTURE.md、docs/CONTRACTS.md、
docs/IMPLEMENTATION_STATUS.md、SETUP_FOR_AI.md 及 AGENTS.md。
只讀這份套件，不讀或複製中心正式系統與資料。
若檔案未提供或你無法讀取來源，先說缺哪些，不假稱已閱讀或執行。

目標固定六項：
1. 設備及檢查表設定。
2. 每日／每月行動檢查，逐項結果、備註及整份簽名。
3. 設備異常通知指定人員，接案、處理、確認與結案歷程。
4. 簡易事件通報與後續追蹤；緊急聯繫仍走既有程序。
5. 私有電子紀錄／PDF 歸檔及授權查詢。
6. 簡易中控台，分開顯示檢查、案件、通知與系統健康。
日常不用 AI 判定，不預填正常、不自動結案，不全員廣播。

請先核對我提供的去識別資料：
- 單位名稱、時區、設備編號與場域。
- 原始日檢／月檢表、檢查方法、作業日與停工日。
- 檢查、處理、確認、檢視及管理角色，用角色代號。
- 各事件的指定接收角色及明確設備／場域範圍。
- 簽名、異常照片、保存／下載與維護需求。
缺項標待確認，不自行補造法規、檢查項目或成效。
不要要求我在對話貼密碼、Token、私鑰、真實名單或私人連結。

先做本機隔離階段：
- 有檔案與終端能力就安裝固定版本依賴，跑 npm test 和 npm run demo，列真實結果。
- 沒有此能力就輸出草稿與待執行命令，明確標未執行。
- 依 schemaVersion 1 產生去識別設定草稿，驗證引用、範圍、角色、日／月需求。
- 可執行時使用 npm run configure -- --input <去識別 JSON 路徑>。
- 設定輸出 .local 私有目錄，不寫入公開原始碼，不覆寫歷史版本。
- 僅補缺少的模組，保持既有業務契約、單一操作入口、防重送與版本核對。
- 不把假身分驗證或記憶體儲存接到公開網站。

登入方式採 Google 登入加管理者核定名單，LINE 僅作通知。
之後提出隔離雲端方案，待我核定帳號與測試範圍：
- 各單位持有自己的 Google／LINE 帳號與資料。
- 只把秘密存私有後端，前端與 GitHub 不含共用管理 Token。
- 私有 Sheets／Drive，不開知道連結者可檢視。
- LINE 每次只通知符合規則的人，發送前重查現在資格與原名單交集。
- API 接受、手機收到、有人接案與結案分開，不混為成功。
- 未完成正式替換層之前，維持 productionAdapters 明確拒絕。
- 依 docs/GOOGLE_TRIAL.md 使用全新 MYSELF 測試專案，空 Google 身分就拒絕。
- clasp 必須指定 -P 隔離目錄，防止尋找到上層正式專案設定。
- 不能把 loopback 的假角色切換部署到公開網站。
- 真實 LINE、部署、觸發器、公開發布分別等我明確同意，不能自行執行。

每輪交付請列：實際改哪些檔案、保持的架構版本、測試命令與結果、
已完成／未完成／需人工確認、是否涉及資料遷移或真實外部操作。
不要說「全部完成」或「一鍵部署成功」，除非有對應的實測與讀回證據。
```

## 架構微調提示詞

```text
我希望調整以下內容：〔填設備、表單欄位、收件規則或畫面需求〕。
請沿 ARCHITECTURE.md 1.1 做最小修改，不改寫整個專案。
先分辨是設定調整、畫面調整、替換層實作或核心契約變更。
保留六項基礎功能、授權範圍、原始紀錄、防重送及故障恢復。
若涉及資料 schema、權限或狀態轉換，先列遷移與回歸測試，再實作。
測試不得發 LINE 或寫正式 Google 資料。
交付實際差異、測試證據與仍待人工核定的事項。
```

## 給新手的短提示

```text
請依這份 ISHA 套件的 START_HERE.md 帶我建置。
先核對我單位的設備、每日／每月表及指定通知角色，使用虛構資料跑隔離範例。
依既定架構產生設定草稿，缺資料請問我。
不要把密碼、Token 或真實名單放進 GitHub，也不要未經同意部署或發 LINE。
先告訴我現在已完成與還缺哪些模組，不將架構原型說成正式上線版。
```
